============================================================
PYTHON PACKAGES: THE GIST ON LOCAL MANAGEMENT
============================================================

1. THE ROLE OF __INIT__.PY
--------------------------
The __init__.py file acts as the "receptionist" for your package. 
It converts a standard folder into a Python package and allows 
you to "hoist" functions to the top level for cleaner imports.

   WITHOUT __init__.py: 
   from my_package.math_utils import add_numbers

   WITH a good __init__.py: 
   from my_package import add_numbers

------------------------------------------------------------
2. IMPLEMENTATION GUIDE
------------------------------------------------------------
Inside "my_package/__init__.py", add the following:

# --- Code Start ---
# Use relative imports (the dot refers to the current folder)
from .math_utils import add_numbers
from .string_utils import clean_text

# Define what is exported during 'from my_package import *'
__all__ = ['add_numbers', 'clean_text'] ************************************this gives more flexibility on what to be imported 
# --- Code End ---

------------------------------------------------------------
3. COMPARISON: IMPORT EXPERIENCE
------------------------------------------------------------
FEATURE          | WITHOUT __INIT__       | WITH __INIT__
------------------------------------------------------------
Import Length    | Long and repetitive    | Short and clean
Namespace        | Reveals internal files | Hides file structure
Star (*) Imports | Imports everything     | Only imports __all__
------------------------------------------------------------

4. BEST PRACTICES FOR LOCAL FUNCTIONS
-------------------------------------
Follow the "Single Responsibility Principle":
- math_utils.py: Only math logic.
- data_utils.py: Only data/dict/list manipulation.
- main.py: Only the high-level logic to run the program.

5. THE CIRCULAR IMPORT TRAP
---------------------------
Avoid "A imports B" while "B imports A". 
If two modules are mutually dependent, Python will crash.
FIX: Move shared logic into a THIRD module (c_utils.py).

------------------------------------------------------------
SUMMARY CHECKLIST
------------------------------------------------------------
[ ] FOLDER NAME: Lowercase, no spaces.
[ ] __INIT__.PY: Must be present in the folder.
[ ] UNIQUE NAMES: Avoid names like math.py (conflicts with Python).
[ ] ENTRY POINT: Keep main.py OUTSIDE the package folder.
